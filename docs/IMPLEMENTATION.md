# PRD 구현 및 검증 현황

기준일: 2026-11-14 · 브랜치: `driving-dashboard`

차량 전용·MVVM/StateFlow·서버/계정 없음 범위를 유지한다. 후속 요청인 “피그마 디자인대로 화면 구현”에 따라 런처 진입을 `DashboardActivity`의 네이티브 Compose로 바꿨다. 기존 CAL 화면은 호스트 연동용으로 보존하며 운전 상태·조회 어댑터·경고 로직을 재사용한다. 후속으로 분류된 캘린더 조회와 목적지 제안도 구현했다. 제조사 전용 권한을 요구하는 실제 졸음 센서와 계기판 제어는 구현했다고 표시하지 않는다.

## Figma 구현 기준

- 원본: [I · Glass — 하단 탐색](https://www.figma.com/design/d5rBNyBSthrjzbVtOfryYr?node-id=150-2954). 홈 `150:3211`/`150:3219`, 휴게소 `150:3227`, 볼거리 `150:3230`, 일정 `150:3233`, 경고 `150:3241`/`150:3259`를 기준으로 구현한다.
- Figma의 글꼴·아이콘·유리 탭을 기반으로 하며 2026-11-15 요청으로 화이트 표면과 타이포그래피를 조정했다. 후속 UX 개선으로 홈은 상단의 운전·휴식 요약과 하단의 동일 너비 휴게소·일정 카드로 구성하고 실제 앱 뷰포트 높이에서 카드 높이를 계산한다. 탭바는 화면 하단 24dp에 고정하고 본문은 각 화면의 정보량에 맞춰 배치한다. 카드 내부에서 운전 시간·속도·휴식 시점을 묶고 휴게소·일정은 카드 전체를 하나의 행동으로 제공한다.
- Noto Sans KR 400/500과 Roboto 운전 숫자, 주간·야간 토큰, Figma SVG 아이콘을 사용한다. 가변 글꼴의 `wght` 축을 명시한다. 원본 SVG는 로컬 에셋으로 유지하고 의미 색은 테마 토큰에 연결한다.
- 유리 탐색은 콘텐츠를 별도 그래픽 레이어에 기록하고 탭 주변 96dp까지 포함해 64dp 블러를 적용한다. 낮은 불투명도의 표면과 반투명 선택 상태를 사용하고 테두리·그림자는 제거했다. 라벨은 별도로 그려 선명도를 유지한다. Figma의 굴절 셰이더 자체와 동일한 엔진은 아니다.
- 휴게소·볼거리는 580:580의 목록·지도 배치다. 실제 지도는 현재 위치·실제 장소 좌표로 투영하며 표시 중인 OSM 타일만 조회하고 최소 7일 캐시한다. 예시 지도는 Figma의 이미지 레이어를 개별 내보내기해 원본 필터까지 보존했다. 예시 좌표와 거리는 디버그 시연에서만 쓴다.
- 차량 화면 바깥의 좌측 자동차·상단 시스템 바·공조 패널은 Pleos OS 영역이다.

## 최종 검증

- `:automotive:assembleDebug`, `:automotive:assembleRelease`, `:shared:testDebugUnitTest`, `:automotive:lintDebug` 통과.
- JVM 회귀 테스트 34개 통과: 운전 상태 17개, 지리 계산 7개, 캘린더 선택 6개, HTTP 요청·파싱·캐시·오류 4개.
- Pleos Connect 2.1.0 에뮬레이터에서 실제 차량 속도 0 km/h, 위치 권한 거부, 캘린더 권한 허용과 일정 선택, 기본 내비게이션 Activity 전달을 확인했다.
- 시연에서 30분 주행, 9분 정차 유지/10분 초기화, 101 km/h 경고·시스템 알림, 2시간 휴식 권고, 졸음 경고와 작은 귀신 아이콘, 확인 후 홈 복귀를 확인했다.
- 서명 전 릴리스 산출물을 로컬 테스트 키로 서명해 콜드 실행과 시연 메뉴 비노출을 확인한 뒤 디버그 APK로 복원했다. 배포 서명은 포함하지 않는다.
- 기존 실험적 R8 `packageScope` 설정은 릴리스에서 Kotlin 컬렉션 상속 클래스의 `IllegalAccessError`를 일으켰다. 차량 모듈의 해당 최적화를 끈 후 재빌드와 실제 릴리스 실행으로 수정 여부를 확인했다.
- 린트 오류는 없다. 기존 라이브러리 린트의 API 호환 경고와 `dataExtractionRules` 권고는 남아 있다.
- 주행 중 실제 차량 신호, 실제 스피커 청감, Car API 6 호스트, 공개 장소 결과와 외부 앱의 도로 길안내는 별도 환경 검증이 필요하다. 테스트용으로 생성한 캘린더 자료는 삭제했다.

### 네이티브 Figma 화면 검증

- 같은 34개 도메인 회귀 테스트와 디버그·릴리스 빌드·린트가 통과했다.
- Pleos 에뮬레이터에서 홈(주간/야간), 휴게소와 볼거리의 1:1 지도·목록, 일정 두 카드, 졸음 경고, 빈 결과와 길안내 실패 화면을 캡처해 Figma와 비교했다. 카드·아이콘·글꼴·탭의 크기와 배치를 확인했다.
- 가변 글꼴이 기본 100 굵기로 표시되는 문제는 400/500 축 지정으로 수정했다. 지도 원본에 포함된 이미지 필터가 일반 에셋 URL에서 누락된 문제는 개별 레이어의 내보내기 이미지로 수정했다.
- 탭 클릭, 테마 전환, 일정 화면에서 경고 발생 후 뒤로 가기로 일정 복귀를 확인했다. 디버그 예시는 명시적인 시연 시작 후에만 표시한다.
- 로컬 테스트 키로 서명한 네이티브 릴리스의 콜드 실행·실제 0분 홈을 확인했다. 디버그 시연 인텐트가 무시되고 설정 화면 하단에 시연 메뉴가 없는 것을 확인한 뒤 디버그 APK로 복원했다.

## 차량 화면에 맞춘 UX 개선

- 사용자 목표는 휴식 시점을 확인하고 가까운 휴게소를 선택하는 것이다. 홈의 채움 버튼은 휴게소 찾기 하나로 유지하고, 휴게소·일정 카드의 중복 버튼을 제거했다.
- 고정된 400dp 홈 카드와 남는 세로 공간을 없애고 `DashboardLayout`에서 헤더·콘텐츠·탭 영역을 함께 계산한다. 휴게소·볼거리·일정·오류 화면도 같은 하단 정렬 기준을 쓴다. 지도 투영과 타일 조회 범위는 실제 지도 크기를 반영한다.
- 숨겨진 GBSW 글자 클릭 대신 ‘설정’을 표시한다. 시연 상태는 헤더 배지로 옮겼다. ‘취소’는 ‘홈으로’, 경고 ‘확인’은 ‘알림 닫기’로 바꿔 행동의 결과를 드러낸다.
- 캘린더 권한 안내에서 바로 연결할 수 있고 거절 경로도 제공한다. 권한을 더 이상 묻지 못하는 상태에서는 반복 요청 대신 앱 설정으로 연결한다. 주기적인 일정 갱신 중에는 기존 일정을 유지한다.
- 시스템 글씨가 큰 경우 홈을 한 열로 재배치하고 스크롤한다. 버튼 높이는 문구에 맞춰 늘어나며 카드·버튼에는 접근성 역할을 제공한다.
- 적용한 비공식 스킬: [toss-inspired-ux](https://github.com/JaceProgramming/toss-inspired-ux/blob/main/skills/toss-inspired-ux/SKILL.md). 토스 공식 제품이나 디자인 시스템을 포함하지 않는다. 제품의 기존 색·폰트·아이콘을 유지한다.
- 판단 근거: [토스의 8가지 라이팅 원칙들](https://toss.tech/article/8-writing-principles-of-toss), [모티베이션을 디자인하기](https://toss.tech/article/design-motivation). 정보의 우선순위·불필요한 문구 제거·행동이 드러나는 버튼을 차량 화면에 맞게 적용했다.

### 이번 변경의 검증

- Pleos 앱 영역 1682×1210px에서 홈·휴게소·일정 화면을 확인했다. 카드 하단과 탭 사이 간격은 디자인 좌표 기준 24dp다. 홈의 휴게소·일정 카드 클릭, 주간·야간 전환, 확대된 지도에서 현재 위치와 장소 마커가 잘리지 않는 것을 확인했다.
- 캘린더 권한 안내의 이점 설명·연결·나중에 버튼을 화면으로 확인했다. ADB 입력 포커스가 불안정해 권한 버튼의 완료 동작과 최종 큰 글씨 스크롤 동작은 검증 완료로 기록하지 않는다. 화면 읽기 도구와 실제 주행 사용성도 별도 검증이 필요하다.
- 디버그·릴리스 빌드, 디버그 린트, 도메인 테스트 34개가 통과했다. 에뮬레이터는 기본 글씨 크기와 야간 운전 홈의 명시적 시연 상태로 복원했다.

### 카드 내부 배치와 유리 탭 추가 조정

- 홈을 상단 운전 요약 카드와 하단 두 개의 동일 너비 카드로 재배치했다. 상단은 운전 시간·속도를 왼쪽, 휴식 알림·진행률·휴게소 찾기를 오른쪽에 묶는다. `SpaceBetween`으로 내용을 멀리 벌리는 대신 4·16·20dp 간격으로 관련 내용을 연결한다.
- 하단 휴게소·일정 카드의 본문 최소 영역과 48dp 행동 행을 맞춰 제목·본문·버튼 기준선을 통일했다. 큰 글씨에서는 한 열로 유지하며 운전 카드 높이를 글씨 배율에 맞춘다.
- 탭바는 주변 96dp 영역까지 샘플링해 64dp 블러를 적용하고 반투명 표면·반사광·이중 가장자리·선택 영역을 겹친다. 아이콘과 텍스트는 블러에서 분리한다. 탭 높이와 카드–탭 간격은 유지한다.
- 디버그·릴리스 빌드와 린트가 통과했다. Pleos에서 새 홈의 카드 클릭 → 휴게소·일정 이동, 주간·야간 전환과 유리 탭을 확인한 뒤 야간 시연 홈을 열어뒀다. 이 변경은 운전 판정과 데이터 로직을 수정하지 않는다.

## 화이트 UI와 보조 화면 정리

- 근거와 적용 값은 [화이트 UI 설계](WHITE_UI.md)에 기록했다. Apple 공식 CarPlay 캘린더 화면, Google 차량 타이포그래피와 Map + Content 가이드, 토스 라이팅 원칙을 확인했다.
- 기본 테마를 화이트로 바꾸고 옅은 회색 배경 위에 흰 카드를 배치한다. 기존 주간·야간 선택은 저장하며 경고도 선택한 테마를 따른다.
- Noto Sans KR 400/500의 자간을 본문 -0.008em·제목 -0.018em으로 맞추고 행간을 4dp 단위로 줄였다. 본문 24/32, 목록 제목 28/36, 화면 제목 32/40을 기준으로 한다.
- 휴게소·볼거리는 1:1 목록·지도를 유지한다. 장소명 아래에 거리와 분류를 모으고 행 끝에 길안내 아이콘을 둔다. 목록 행은 내용에 맞춰 높이가 늘어나며 제목·거리·행동의 정렬을 통일한다.
- 일정의 세로 카드 두 장을 내용 높이에 맞는 한 장으로 바꿨다. 시간·제목이 윗줄, 목적지·길안내가 아랫줄에 붙는다. 빈 일정·권한 안내·오류도 설명과 복구 버튼을 가까이 배치한다.

### 화이트 UI 검증

- Pleos Connect 2.1.0의 앱 영역 1682×1210px에서 홈·휴게소·볼거리·일정을 캡처했다. 화이트 테마 저장과 재실행, 네 탭 전환, 1:1 목록·지도 배치, 시간·제목의 상단 정렬과 목적지 옆 버튼을 확인했다.
- 시연 일정에서 길안내 버튼을 눌러 내비게이션 미설치 상태로 이동하고, ‘일정으로’ 버튼으로 기존 일정에 복귀했다. 빈 일정 안내도 캡처했다.
- 시스템 글씨 배율 2.0 확인 시 에뮬레이터가 정상 화면을 유지하지 못해 큰 글씨 스크롤은 검증 완료로 기록하지 않는다. 설정은 원래 1.0으로 복원했다. 기본 크기 화면을 기준으로 시각 검증했다.
- 이번 변경의 디버그·릴리스 빌드와 디버그 린트가 통과했다. 화이트 휴식 경고의 아이콘 대비를 확인하고 최신 APK의 화이트 일정 화면을 열어뒀다. 운전·조회 도메인 로직 변경은 없으며 기존 34개 도메인 테스트는 이 시각 변경에서 반복 실행하지 않았다.

### 일정 화면의 전체 간격 재조정

아래의 48dp 내부 간격 조정은 후속 ‘일정 정보 밀도와 안팎 간격’ 변경으로 대체했다.

- 일정 영역의 세로 중앙 정렬을 제거하고 날짜·새로고침을 화면 헤더 바로 아래에 붙였다. 날짜 헤더 → 카드 간격은 24dp다.
- 카드 밖의 안내문을 길안내 버튼과 같은 하단 행에 넣었다. 시간·제목, 목적지, 안내문·실행 버튼을 세 구역으로 나눠 내용의 흐름으로 높이가 정해지게 했다.
- 높은 차량 뷰포트에서는 48dp 내부 간격을 사용한다. 콘텐츠 높이가 660dp보다 낮거나 큰 글씨인 경우 내부 간격을 줄이고, 낮은 화면에서는 날짜를 한 줄로 묶는다. 하단 탭의 위치는 다른 화면과 같다.
- Pleos 1682×1210px 앱 영역에서 날짜와 카드 간격 24dp, 카드와 탭 사이 약 44dp를 확인했다. 디버그·릴리스 빌드와 린트 통과. 길안내 버튼 → 오류 → 일정 복귀, 휴게소 탭 왕복을 확인하고 최종 화이트 일정 화면을 열어뒀다. 낮은 화면·큰 글씨 분기는 이번 반복에서 별도로 실행하지 않았다.

### 일정 정보 밀도와 안팎 간격

카드 내부 밀도는 유지하며, 아래의 헤더·탭 중앙 배치는 후속 ‘일정 헤더와 탭바 고정’ 변경으로 대체했다.

- 높은 화면에서 카드 내부를 48dp씩 벌리던 분기를 제거했다. 기본 시연 카드는 약 544dp에서 164dp 높이로 줄었다. 시간 / 제목·목적지 / 길안내 버튼을 한 행에 묶고, 제목과 목적지는 12dp 간격으로 연결한다. 내부 여백은 28dp, 열 간격은 24dp다.
- 카드와 탭의 폭을 928dp로 맞췄다. 헤더·한 줄 날짜·카드·탭을 한 묶음으로 중앙 배치하며, 사이 간격은 각각 20·16·24dp다. 남는 화면 높이를 카드 내부나 카드–탭 사이에 배분하지 않는다. 일정 화면의 탭은 카드 바로 아래에 놓인다.
- 내용이 길거나 글씨가 큰 경우 본문 영역만 최대 가용 높이 안에서 스크롤하고 탭은 계속 접근할 수 있게 했다. 큰 글씨에서는 길안내 버튼이 제목·목적지 아래로 이동한다. 실제 큰 글씨·낮은 화면 검증은 이 반복에 포함하지 않는다.
- 분리한 일정 화면에 캘린더 상태와 길안내 오류를 명시적으로 전달해 Compose가 화면 갱신을 생략하지 않게 했다. 실제 클릭으로 오류 화면 전환과 ‘일정으로’ 복귀, 휴게소 탭 왕복, 빈 일정에서 새로고침 후 시연 일정 표시를 확인했다.
- 디버그·릴리스 빌드와 디버그 린트가 통과했다. Pleos 1682×1210px 앱 영역, 기본 글씨 크기 1.0과 화이트 테마에서 캡처했다. 에뮬레이터에는 수정된 화이트 일정 화면을 열어둔다. 운전·데이터 도메인 로직은 변경하지 않았다.

### 일정 헤더와 탭바 고정

- 일정 화면 전체를 세로 중앙에 묶던 구조를 제거했다. 공통 `PageHeader`는 상단 24dp, `GlassTabs`는 하단 24dp에 고정하며 다른 탭과 같은 좌표를 사용한다.
- 날짜와 일정 카드는 헤더 아래 24dp부터 위로 정렬한다. 날짜–카드는 16dp 간격으로 붙이며, 남는 높이는 카드 아래에 둔다. 길면 이 콘텐츠 영역만 스크롤한다. 오류·권한·빈 일정 상태에서도 헤더와 탭바의 위치는 그대로다.
- 카드의 기존 구현은 변경하지 않았다. 폭 928dp, 기본 시연 높이 약 164dp, 내부 여백 28dp, 열 간격 24dp, 제목–목적지 12dp, 버튼 216×64dp와 날짜–카드 16dp 간격을 유지한다.
- 디버그·릴리스 빌드와 디버그 린트가 통과했다. Pleos 1682×1210px, 화이트 테마와 글씨 배율 1.0에서 일정·길안내 오류 화면의 고정 위치와 복귀, 휴게소 탭 왕복을 확인했다. 큰 글씨·낮은 화면의 실행 검증은 이번 변경에 포함하지 않았다.

### 일정 왼쪽 정렬과 외곽 장식 제거

- 일정 날짜·카드의 왼쪽 좌표를 176dp에서 헤더와 같은 48dp로 변경했다. 폭 928dp와 내부 배치는 유지하며 하단 탭바는 기존 하단 중앙 위치에 고정한다.
- 공통 카드의 1dp 테두리, 탭바의 그림자·이중 외곽선·선택 영역 테두리를 제거했다. 탭바의 반투명 배경과 블러는 유지한다.
- 디버그·릴리스 빌드와 디버그 린트가 통과했다. 최신 APK를 Pleos 에뮬레이터에 설치하고 화이트 일정 화면에서 왼쪽 정렬, 테두리와 그림자 제거, 촘촘한 카드 배치와 고정 탭바를 직접 확인했다. 화면을 열어둔 채 실제 캡처를 저장했다.

## 시간과 상태의 규칙

- 속도 데이터가 유효할 때만 시간을 진행한다. 속도를 잃으면 측정을 멈추며, 모르는 시간을 정차로 계산하지 않는다.
- 속도 입력이 5초 이상 갱신되지 않으면 `속도 정보 없음`으로 전환한다.
- 실제 운전 누적 시간과 경고 재알림 잔여 시간을 15초마다 저장하고 Session 종료 시 저장한다.
- 재실행 시 운전 누적 시간만 복원한다. 앱이 꺼져 있던 시간을 운전/휴식으로 추측하지 않는다.
- 시연 시간과 실제 시간·재알림 제한을 분리한다. 시연 자료로 실제 운전 기록을 덮어쓰지 않는다.
- 경고 확인은 해당 원인에만 적용한다. 원인이 계속 유지되면 5분/30분 제한 이후 다시 알린다.

## 데이터와 개인정보

- GPS 좌표와 범위를 Overpass로, 현재 지도 범위의 타일 좌표(z/x/y)를 OSM 타일 서버로 전송한다. 캘린더 제목·장소는 장소 조회 서버로 보내지 않는다.
- 일정 장소는 사용자가 길안내를 확인한 경우에만 기기 내 내비게이션 앱으로 전달한다.
- 장소 거리와 진행 방향 필터는 직선거리·현재 방위 기준이다. 실제 고속도로 진입 가능 여부/도로 거리/전체 경로 매칭을 보장하지 않는다.
- 장소 출처: © OpenStreetMap contributors. 조회 결과는 5분/1 km 범위에서 재사용한다.
- 공개 Overpass는 시연용 외부 의존성이며 응답과 데이터 커버리지를 보장하지 않는다. 배포용 서비스에는 전용/계약된 장소 제공자를 준비해야 한다.
- 실제 위치·일정·운전 기록은 디버그 로그나 분석 서버로 전송하지 않는다.

## 플랫폼 제약

- 현재 설치된 Pleos Connect 2.1.0은 Android API 34 / Car API 4이다. 네이티브 런처 화면은 CAL 호스트 배치에 의존하지 않는다.
- 이 Pleos 이미지는 `android.car` API를 시스템 부트 클래스 경로로 제공하고 별도 공유 라이브러리 이름은 등록하지 않는다. 라이브러리 필수 설치 조건을 두지 않으며 SDK의 차량 속도 리스너를 사용한다.
- 기존 CAL 지도는 테스트 렌더러이나 네이티브 지도는 별도의 실제 타일 뷰다.
- 실제 졸음 상태 프로퍼티는 일반 앱에 허용되지 않는 제조사 서명/특권 권한을 요구한다. 계기판 제어도 일반 POI 앱의 범위 밖이다.

근거: [Car Hardware API](https://developer.android.com/training/cars/apps/library/car-hardware-api), [운전자 모니터링 권한](https://developer.android.com/reference/android/car/VehiclePropertyIds#DRIVER_DROWSINESS_ATTENTION_WARNING), [템플릿 단계 제한](https://developer.android.com/training/cars/apps/library/template-restrictions), [Overpass 사용 안내](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html).

네이티브 지도 정책: [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/). 글꼴 출처와 OFL 라이선스는 `automotive/src/main/assets/licenses/NotoSansKR-OFL.txt`에 포함한다.

### 일정 카드 양끝과 내부 열 정리

- 카드와 날짜 행을 좌우 48dp·폭 1184dp로 맞춰 헤더 기준선과 통일했다.
- 시간·제목·목적지·길안내를 네 열로 배치하고 32dp 열 간격, 8dp 라벨–값 간격을 적용했다. 카드 높이 약 164dp, 내부 여백 28dp와 테두리·그림자 없는 표면을 유지했다.
- 디버그·릴리스 빌드와 디버그 린트 통과. Pleos 최신 APK의 실제 캡처를 확인했으며 하단 탭 영역은 이전 캡처와 픽셀이 일치한다. 커밋하지 않았다. 큰 글씨·다른 높이 화면은 이번 검증에 포함하지 않았다.

### 네 화면 디자인 리뷰와 일정 기준선 수정

- 일정의 서로 다른 크기 열을 각각 세로 중앙 정렬하던 방식을 없앴다. 공통 라벨 행과 본문 행을 측정해 각각 FirstBaseline으로 배치한다. 목적지는 내용 너비로 측정하고 20dp 뒤에 길안내를 붙인다. 카드 외곽은 좌우 48dp, 내부 여백은 28dp다.
- 홈의 두 보조 카드 제목과 거리 크기를 32sp로 통일하고 제목–본문 간격을 8dp로 정리했다.
- 휴게소·볼거리는 목록과 지도 1:1을 유지하면서 목록 헤더·행의 좌우 여백을 28dp로 맞췄다. 길안내 문구를 각 행의 행동 옆에 표시하고 반복 안내 푸터를 제거했다.
- 디버그·릴리스 빌드와 린트 통과. Pleos 1682×1210px에서 네 화면을 실제 캡처해 확인했다. 하단 탭바 구현을 변경하지 않았다. 큰 글씨·다른 뷰포트는 이번 시각 검증에 포함하지 않는다. 사용자 지시에 따라 커밋하지 않았다.

### 일정 정보 묶음의 가로 간격

- 제목 열에 남는 폭을 모두 배분하던 방식을 제거했다. 제목은 내용에 맞춰 160~240dp, 정보 열 사이 24dp, 목적지–버튼 20dp로 제한한다. 내용 전체 묶음의 양쪽에 남는 폭을 균등 배치한다.
- 라벨·본문의 공통 기준선, 카드 좌우 48dp와 폭 1184dp, 하단 탭바를 유지했다.
- 디버그·릴리스 빌드와 lintDebug 통과. Pleos 실제 화면에서 카드 양끝(x=48~1231)을 확인했으며 하단 탭 영역은 이전 캡처와 픽셀이 동일하다.

### 일정 카드 내부 양끝 고정

- 가운데 묶음 배치를 제거하고 시간 왼쪽과 길안내 오른쪽을 카드 내부 여백 28dp에 고정했다. 제목 열은 내용 너비에 맞추고 세 간격에 남는 폭을 균등 배분한다. 라벨·본문 공통 기준선과 카드 외곽 좌우48dp는 유지한다.
- 최신 APK의 Pleos 실제 캡처로 확인했다. 디버그·릴리스 빌드 및 린트 통과. 하단 탭 소스와 전후 캡처 픽셀이 동일하다. 커밋하지 않았다.

### 홈·휴게소·볼거리 내부 정렬 보완

- 홈 상단 두 영역의 라벨 높이를 맞추고 카드 내부28dp, 제목–값8dp, 정보구역16dp로 정리했다. 운전 숫자를88sp로 조정하고 속도·거리의 기준선을 맞췄다. 주요 버튼과 하단 카드 행동은 오른쪽 기준선을 사용한다.
- 휴게소·볼거리의 헤더/건수, 번호/장소명/길안내의 첫 기준선을 맞췄다. 설명24sp와 제목–설명8dp 간격을 유지한다.
- 디버그·릴리스 빌드와 lintDebug 통과. Pleos 세 화면을 실제 캡처하고 홈 버튼→휴게소, 볼거리 탭 이동, 홈 복귀를 캡처 비교로 확인했다. 탭바·일정 구현 변경 없음. 탭 캡처 비교에서 휴게소·볼거리는 픽셀 동일, 홈은 반투명 표면의 RGB 차이 최대1이며 위치·형태는 동일하다.
- 큰 글씨·다른 뷰포트·외부 도로 길안내는 이번 검증에 포함하지 않았다. 커밋하지 않았다.
